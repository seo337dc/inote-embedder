# A3 결과 — 로컬 pgvector에서 내 공개 글의 가까운 이웃 확인 (2026-10-12)

## 한 일
- 로컬 Postgres + pgvector 컨테이너(`pgvector/pgvector:pg17`, 이미지 637MB, pgvector 0.8.7) — **운영 DB와 완전히 분리**
- 배포된 BE의 **공개 목록 API**에서 공개 글 **22개**를 가져옴(카테고리 8종, 본문 합계 34,747자). 비공개·미발행 글은 API가 내려주지 않고, 스크립트가 한 번 더 걸러서 알린다(이번엔 0개)
- 임베딩 텍스트 = `제목 + 본문 앞부분`(최대 1,500자), **카테고리는 넣지 않음**
- 22개 임베딩 **약 179초**(배치 4개씩). 다시 실행하면 해시가 같아 **0개** 계산(건너뜀 확인)

## 한눈에 훑은 이웃 (`python -m lab.neighbors --all`) — 사람 눈에 납득됨
- Docker 글끼리: 0.66~0.78 (Docker / 상세히 / 보충 설명 / Volume)
- FE·BE 테스트 글끼리: 0.70~0.75
- 호스팅 정리 ↔ DB 이전: 0.717
- 임베딩 ↔ 하네스 AI 구축: 0.711, LLM / LangChain / 토큰 → 같은 AI 묶음
- 내용 없는 글("tttttt", "테스트 테스트")은 최고 이웃 점수가 0.40~0.52로 **낮다** → 억지 추천을 막는 최소 기준(τ_min)이 실제로 걸러 줄 수 있다

## 점수 분포
- 글마다 **가장 가까운 이웃** 점수: 최소 0.398 / 중앙값 **0.709** / 최대 0.779
- 전체 231쌍: 평균 **0.451** / 최소 0.235 / 최대 0.779
- → 무관한 쌍은 대체로 0.25~0.5, 비슷한 글은 0.65~0.78. **"비슷한 글" 기준은 대략 0.6 안팎에서 시작해 평가 세트로 조정**해 볼 만하다(PLAN B·C의 τ). 표본이 작아 아직 확정값이 아니다.

## 카테고리 제안 정확도 (자기 자신 제외, 이웃 투표 `python -m lab.neighbors --eval`)
| 설정 | 1순위 적중 | 상위 3개 안 |

| k=3 | 12/22 (55%) | 16/22 (73%) |
| **k=5** | **13/22 (59%)** | **17/22 (77%)** |
| 기준선(항상 '사이드프로젝트 기록') | 36% | |

해석할 때 주의:
- **카테고리가 글 1개뿐인 4개(이직·프론트엔드·백엔드·알고리즘)는 구조상 맞힐 수 없다.** 맞힐 수 있는 18개 중 13개 적중 = **약 72%**.
- 틀린 사례는 대부분 **사람이 붙인 카테고리 자체가 겹치는 경우**다: `LLM이란 무엇인가`(학습) → AI, `토큰 이해`(학습) → AI, `KURE를 활용한…`(사이드프로젝트 기록) → DevOps/AI. 모델이 틀렸다기보다 카테고리 경계가 모호하다.
- 내용 없는 테스트 글 2개는 제안 근거 자체가 없다 → 최소 점수 기준으로 "제안하지 않음"이 맞다.
- 표본 22개라 수치는 **방향 확인용**이다. 글이 늘고 평가 세트(A7)가 생기면 다시 잰다.

## 발견한 점 (설계에 반영할 것)
1. **배치 임베딩은 글당 약 8초**(179초/22개)로, 앞서 잰 단일 1,150자 약 2.6초보다 느리다 → 긴 글이 섞인 배치는 가장 긴 글에 맞춰 길어진다. 글 저장 시 **한 편씩** 계산(A5)하는 편이 낫다.
2. **내용 없는 글은 점수로 걸러진다**(최고 이웃 0.40). 짧은 글·테스트 글은 임베딩 대상에서 빼거나(최소 본문 길이) 최소 점수로 거를지 정해야 한다.
3. 카테고리 제안(C)은 **가중 투표 + 최소 점수**로 동작함을 확인했다. 카테고리가 겹치는 경우를 위해 **상위 3개 제안**(1개만 강요하지 않기)이 맞아 보인다.
